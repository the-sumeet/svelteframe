`OffthreadVideo` shows a video file inside a composition. In a render it asks `ffmpeg` for **exactly** the right frame, so it is frame-accurate: a browser's own `<video>` element cannot be relied on to land on the right frame while the renderer steps.

```svelte
<div style="position:relative;width:420px;height:236px;overflow:hidden">
  <OffthreadVideo src="/media/clip.mp4" />
</div>
```

## Props

| Prop | Default | Meaning |
| --- | --- | --- |
| `src` | required | The video file. A relative path is resolved against the page. |
| `startFrom` | `0` | Frames of the source to skip. |
| `endAt` | the end | Frame of the source at which to stop showing it. |
| `volume` | `1` | A gain, or a function of the frame, as for [`Audio`](/concepts/audio/). |
| `playbackRate` | `1` | Speed. `0.5` is slow motion. |
| `muted` | `false` | Leave out the video's sound. |
| `fit` | `'contain'` | How the picture fills its box: `contain`, `cover`, `fill`, `none` or `scale-down`. |
| `class`, `style` | none | Applied to the picture element. |

The picture fills its parent (`width: 100%; height: 100%`). Outside its range (before a `Sequence` starts, or after `endAt`) it is hidden.

## Which frame is shown

The video is read at `(startFrom + frame × playbackRate) / fps` seconds. The frame shown is the **last one that starts at or before that time**, which is how a player behaves. So a 24 fps video in a 30 fps composition repeats some frames, and a slow-motion `playbackRate` repeats more. Past the end of the file the last frame stays.

## Sound

Unless `muted`, the video's audio is recorded and mixed like [`Audio`](/concepts/audio/), with the same trimming, speed and volume. A video with **no audio track** is fine: it is simply skipped when mixing.

## In a preview and in a render

- **Preview:** a normal `<video>` element, kept at the time of the current frame. It plays with the `Player` and also plays its sound.
- **Render:** an image of the frame, decoded by `ffmpeg`. The page asks the renderer for it at `/__svelteframe/video-frame`, and the renderer answers that request itself, so your project needs no server code. Each file is downloaded once, and frames are cached briefly for repeated requests.

Frames are sent as JPEG, or as PNG when you render with `--png`.

<Aside type="caution" title="Position the box">
  A [`Sequence`](/concepts/timeline/) fills its nearest positioned parent. If you put an `OffthreadVideo` in a `Sequence` inside a smaller box, make that box `position: relative` or the video will cover the whole composition.
</Aside>

## Notes

- The source must be reachable by URL from the renderer (a file served by your project, or any `http` or `https` address). A video that cannot be read fails the render with the reason, for example `has no video stream`.
- Each frame starts an `ffmpeg` process, so videos cost more to render than shapes. Rendering with several workers helps.
